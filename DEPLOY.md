# Dvis на Netlify — пошаговая инструкция

Сайт `https://dvisan.netlify.app` на момент проверки отдаёт **404**. Это значит, что Netlify-проект либо не создан, либо не привязан к репозиторию, либо домен не подключён. Код в GitHub уже актуальный (`main`), нужно только подключить деплой.

Ниже — рабочий порядок. Всё бесплатно.

---

## 1. Проверьте репозиторий

- Репозиторий: `https://github.com/angars2013angars-bit/dvigram`
- Ветка: `main`
- Последний коммит должен содержать вход по нику/паролю и звонки.

Если вы вносили изменения локально — сначала запушьте:

```bash
git add -A
git commit -m "Описание изменений"
git push origin main
```

---

## 2. Создайте сайт в Netlify

1. Войдите в <https://app.netlify.com> (лучше через GitHub — так репозитории видны сразу).
2. **Add new site → Import an existing project**.
3. Выберите **GitHub** и репозиторий `dvigram`. Если он не виден — нажмите **Configure Netlify on GitHub** и разрешите доступ к репозиторию.
4. Branch to deploy: **main**.
5. Netlify сам прочитает `netlify.toml`:
   - Base directory: пусто
   - Build command: `npm run build`
   - Publish directory: `dist`
   - Functions directory: `netlify/functions`
   - Node version: `22` (указано в `netlify.toml`, поэтому `.nvmrc` не обязателен)
6. **Deploy site**.

После деплоя откройте вкладку **Deploys** и дождитесь статуса **Published**. Если статус **Failed** — откройте лог и смотрите ошибку (чаще всего это версия Node или отсутствующий `package.json`).

---

## 3. Проверьте, что Functions собрались

В логе деплоя должна быть строка про functions, а в разделе **Functions** сайта должен появиться `api`.

Проверка через Terminal на своём компьютере:

```bash
curl -X POST "https://ВАШ-САЙТ.netlify.app/.netlify/functions/api?action=me" \
  -H "Content-Type: application/json" \
  -d "{}"
```

Ожидаемый ответ: JSON вида `{"user":null}`.

- Если приходит HTML или 404 → Functions не подключились. Проверьте `netlify.toml`:
  ```toml
  [build]
    command = "npm run build"
    publish = "dist"
    functions = "netlify/functions"
  ```
- Если приходит `{"error":"..."}` → Function работает, это уже хорошо.

---

## 4. Проверьте Netlify Blobs

Blobs на Netlify включаются автоматически, никаких переменных окружения добавлять не нужно. Хранилище называется `dvis-data`; оно создастся при первом же создании аккаунта.

В разделе сайта **Data → Netlify Blobs** после первого аккаунта появятся ключи `users/...`, `sessions/...` и т.д.

---

## 5. Подключите домен `dvisan.netlify.app`

Если хотите именно этот адрес:

1. **Site settings → Domain management → Custom domains → Add custom domain**.
2. Введите `dvisan.netlify.app`. Netlify сам добавит нужные DNS-записи, если домен куплен через Netlify.
3. Если домен у другого регистратора — добавьте в его DNS:
   - `CNAME` `dvis` → `ВАШ-САЙТ.netlify.app`
   - или `A` → `75.2.60.5` (IP Netlify)
4. Дождитесь проверки DNS (до нескольких часов). SSL Netlify выпустит бесплатно автоматически.
5. Пока DNS не подключится, используйте адрес вида `https://dvis-xxxxxx.netlify.app` из раздела **Overview**.

---

## 6. Отключите бейдж Netlify

Чтобы бейдж точно не мешал кнопке отправки:

**Project configuration → General → Powered by Netlify badge → выключить**.

В коде бейдж всё равно скрывается автоматически, но выключение в настройках — самый надёжный вариант.

---

## 7. Проверка «как пользователь»

1. Откройте сайт на телефоне. Должна появиться заставка, затем экран входа.
2. Создайте аккаунт: ник (3–24 символа) и пароль (от 6 символов).
3. Обновите страницу — вход должен восстановиться **сам**, без формы.
4. В настройках создайте код приглашения, отправьте его второму человеку.
5. Второй человек создаёт свой аккаунт и вводит код в **«Приглашения → Войти по коду»**.
6. В личном чате нажмите кнопку звонка. Разрешите микрофон.

### Если забыли пароль

На экране входа введите ник и новый пароль, нажмите **«Не помню пароль — сменить на этом устройстве»**. Это работает только на устройстве, где уже был вход в этот аккаунт.

---

## 8. Звонки: обязательные условия

- **HTTPS** — на Netlify есть автоматически. На `http://localhost` тоже работает.
- **Разрешение микрофона** в браузере. На iPhone — Safari, доступ к микрофону для сайта.
- **Два разных аккаунта в одном чате** (через приглашение). В демо-режиме `npm run dev` данные лежат в localStorage каждого браузера, поэтому два разных браузера друг друга не увидят — для звонков нужен настоящий деплой.
- **Оба абонента онлайн**: сигналинг опрашивается раз в ~1,3 с.
- Без TURN-сервера звонок может не пройти через жёсткий NAT или мобильный интернет с симметричным NAT. Free TURN-серверов надёжно нет; для стабильных звонков нужен платный TURN.

Если звонок «не работает» — проверьте именно эти пункты, прежде чем менять код.

## Частые проблемы

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Сайт отдаёт 404 | Сайт не создан / домен не привязан / деплой не Published | Разделы 2 и 5 |
| `Сервер Dvis не найден` | Functions не задеплоены | Раздел 3 |
| `Неверный ник или пароль` | Старый аккаунт создан по ключу, или пароль введён неверно | Смените пароль на своём устройстве (раздел 7) |
| Выкидывает из аккаунта | Истекла сессия | Должно чиниться само; если нет — проверьте, что задеплоен последний коммит |
| Звонок не соединяется | Нет HTTPS / микрофона / второй абонент не в чате | Раздел 8 |
| `Netlify CLI падает` на Node 26 | CLI несовместим с Node 26 | Используйте Node 22: `nvm use` |

## Локальный деплой через CLI (по желанию)

На этой машине Netlify CLI **не авторизован** — при `netlify deploy` открывается окно логина в браузере. Поэтому деплой нужно сделать через сайт <https://app.netlify.com> (раздел 2) или авторизоваться вручную:

```bash
nvm use          # Node 22, иначе CLI падает на Node 26
npx netlify login
npx netlify link
npx netlify deploy --prod
```

`npx netlify dev` — для локальной проверки Functions с Node 22.
