# Dvis — анонимный мессенджер

**Сайт: <https://dvisan.netlify.app>**

Dvis — минималистичный анонимный мессенджер на **Vite + ванильный JavaScript + Netlify Functions + Netlify Blobs**. Полностью чёрно-белый интерфейс в стиле Signal. При первом запуске показывается атмосферная заставка, затем приложение само определяет тип устройства: на телефоне — обычный мобильный экран, на ПК — телефоноподобная колонка/двухпанельная раскладка по центру.

Главное: **никаких телефонов, почты, логинов и каталога**. При создании аккаунта один раз выдаётся короткий ключ `DV-XXXX-XXXX`. Он привязывается к устройству, поэтому даже короткий код бессмысленно подбирать со стороны. Людей можно добавить **только по приглашению в чат**.

---

## Как это работает

1. На старте — заставка с надписью **«Желательно: Tor +VPN + Brave»**. Нажмите на неё или дождитесь окончания анимации.
2. Нажмите **«Создать аккаунт»**. Ключ вида `DV-AB3K-9QWE` показывается **один раз**. Скопируйте его.
3. Ключ работает только на этом устройстве. Он хранится в `localStorage`, `sessionStorage` и cookie браузера, поэтому случайная очистка одного хранилища не «выкидывает» аккаунт. При полной очистке данных браузера восстановить его нельзя: нет пароля, почты и серверной копии ключа. В настройках ключ можно показать или скопировать сразу, без перезагрузки.
4. В настройках создайте код приглашения `DVS-XXXX-XXXX-XXXX` и отправьте его собеседнику.
5. Собеседник создаёт свой аккаунт и вводит код в **«Приглашения → Войти по коду»**. Чат появляется у обоих.
6. В личном чате доступна кнопка звонка: аудио идёт напрямую между устройствами через WebRTC, Netlify используется только для сигналинга (offer/answer/ICE).

## Что есть

- ⚪ **Полностью чёрно-белый дизайн**: фон `#000`, белые акценты, инверсные исходящие пузыри, монохромные аватары с инициалами.
- 🎬 **Красивая заставка**: сетка, вращающееся кольцо, glitch-эффект логотипа, прогресс-бар и рекомендация `Tor + VPN + Brave`.
- 🔑 **Короткий ключ `DV-XXXX-XXXX`** (8 символов из алфавита без похожих `0/O/1/I`). Выдаётся один раз, затем хранится только на устройстве; сервер хранит `scrypt`-хэш и соль.
- 📱 **Привязка к устройству**: сервер сверяет хэш устройства из заголовка `X-Dvis-Device` с дублем в cookie. ID устройства также дублируется в `localStorage`/`sessionStorage`, поэтому ключ не «вылетает» после частичной очистки хранилища. Ключ с другого устройства не подойдёт.
- 🖥️ **Автоопределение интерфейса**: мобильный UA + узкий экран → телефонная версия; широкий экран с мышью → ПК-версия с отдельным списком чатов. При повороте/изменении окна раскладка переключается автоматически.
- 🙈 **Анонимность**: имя — только подпись в чате, не ищется. Никакого каталога пользователей.
- 🔒 **Только приглашения**: код одноразовый по умолчанию, можно сделать многоразовым (до 50 входов), отозвать или дождаться истечения срока (7 дней).
- 💬 **Переписка**: отправка, ответы, реакции, удаление у всех, двойные галочки прочтения, непрочитанные, обновление раз в ~2,2 с с паузой в скрытой вкладке.
- 📞 **Аудиозвонки**: WebRTC + сигналинг на Netlify Functions/Blobs. Кнопка ввода/отбоя, входящий экран, таймер, микрофон вкл/выкл.
- 📲 **PWA**: манифест, иконки, service worker; на телефон можно поставить как приложение.
- 🧪 **Демо-режим**: если Functions недоступны (`npm run dev`), всё работает локально через `localStorage` с префиксом `dvis:*`.

Бейджи «Made by Netlify» и «Powered by Netlify» скрываются CSS и JS-наблюдателем. Netlify рендерит новый бейдж в изолированном iframe (`#nl-badge-frame`, `z-index: 2147483645`), поэтому скрывается сам iframe — иначе он перекрывал кнопку отправки на телефоне. На API `/.netlify/functions/api` это не влияет.

## Звонки: как это устроено

Звук **не идёт через Netlify** — это было бы дорого и медленно. Netlify Functions хранит только сигналинг:

| Action | Назначение |
| --- | --- |
| `call.start` | создать звонок в личном чате |
| `call.signal` | передать `offer`, `answer` или ICE-кандидат |
| `call.active` | отметить начало разговора |
| `call.end` | завершить |
| `calls.list` | проверить входящий/текущий звонок |

Клиент каждые ~1,3 с опрашивает `calls.list`, показывает входящий вызов и поднимает `RTCPeerConnection`. ICE-кандидаты пишутся отдельными ключами Blobs, поэтому параллельные сигналы двух участников не перетирают друг друга; ответчик отправляет свои кандидаты сразу после `setLocalDescription`, а не после смены статуса. Повторные опросы не применяют кандидаты дважды. Используются публичные STUN-серверы Google. Для сложных NAT может понадобиться TURN-сервер с ключами — в бесплатном деплое его нет, поэтому в редких случаях соединение не установится.

Требования: **HTTPS** (на Netlify он есть автоматически) и разрешение браузера на микрофон.

## Быстрый запуск

### Без сервера

```bash
npm install
npm run dev
```

Откройте <http://localhost:5173>. Данные останутся только в этом браузере.

### С сервером

Рекомендуется **Node.js 22** (есть `.nvmrc`):

```bash
nvm use
npm install
npx netlify dev
```

Откройте <http://localhost:8888>. Работают настоящие ключи, cookie, Functions и Blobs. Без `npx netlify link` Blobs локально заменяются памятью процесса.

> Если `netlify dev` падает с `Cannot read properties of undefined (reading 'prototype')`, переключитесь с Node 26 на Node 22.

## API

Все запросы — `POST /.netlify/functions/api?action=...` с JSON-телом и заголовком `X-Dvis-Device`; cookie сохраняются автоматически.

| Группа | Actions |
| --- | --- |
| Аккаунт | `account.create`, `account.login`, `account.logout`, `me`, `profile.update` |
| Чаты | `chats.list`, `chat.update`, `chat.leave` |
| Приглашения | `invite.create`, `invite.list`, `invite.revoke`, `invite.join` |
| Сообщения | `messages.list`, `messages.send`, `messages.read`, `messages.react`, `messages.delete` |
| Звонки | `call.start`, `call.signal`, `call.active`, `call.end`, `calls.list` |

Приглашение живёт 7 дней. Одноразовый код после входа становится неактивным; многоразовый — до 50 входов. Отзыв мгновенный.

## Хранение данных

Netlify Blobs (`dvis-data`) использует ключи:

```text
users/<id>              пользователь (хэш ключа + хэш устройства)
keys/<sha256>           поиск пользователя по ключу
sessions/<sha256>       сессия
chats/<id>              чат и участники
messages/<id>           сообщения чата
invites/<code>          приглашения
calls/<chatId>          текущий звонок (offer/answer/статус)
call-signals/<chatId>/<callId>/<id>  отдельные ICE-кандидаты
indexes/users|chats|invites
ratelimit/<key>         защита от перебора ключей
```

В демо-режиме те же данные лежат в `localStorage` с префиксом `dvis:local:`. Ключ для копирования хранится локально как `dvis:key` (плюс резерв в `sessionStorage` и cookie `dvis_key`) — сервер повторно его не возвращает. ID устройства хранится как `dvis:device` с дублем в cookie `dvis_device`.

## Деплой на Netlify (бесплатно)

1. Запушьте код в GitHub.
2. На <https://app.netlify.com>: **Add new site → Import an existing project**.
3. Настройки уже в `netlify.toml`: build `npm run build`, publish `dist`, functions `netlify/functions`, Node `22`.
4. **Deploy site**. Проверьте <https://dvisan.netlify.app>.
5. Обновления приходят после `git push`. Свой домен подключается в **Site settings → Domain management**; SSL бесплатный.

Проверка после деплоя: создайте аккаунт, скопируйте ключ, во втором браузере создайте другой аккаунт, в первом — приглашение, во втором — вход по коду. Затем нажмите звонок в личном чате и разрешите микрофон.

## Ограничения

- Нет end-to-end шифрования: сервер видит текст сообщений и сигналинг звонка.
- Нет восстановления ключа после полной очистки браузера и переноса аккаунта на другое устройство — это осознанная модель привязки. Частичная очистка хранилища и истёкшая сессия переживаются: приложение тихо перелогинивается по сохранённому ключу и не просит вводить его заново.
- Звонки только аудио и только в личных чатах. Нужен HTTPS и микрофон.
- Без TURN-сервера звонок может не пройти через жёсткий NAT.
- Сообщения обновляются polling’ом (~2,2 с), звонки — опросом сигналинга (~1,3 с).
- История ограничена последними 1000 сообщениями на чат; подгрузка — по 40.

## Частые проблемы

**Ключ не подходит.** Он привязан к устройству. Проверьте формат `DV-XXXX-XXXX`, регистр и пробелы/дефисы — они допустимы.

**Приложение снова просит ключ во время работы.** Обычно это истёкшая cookie-сессия: приложение само перелогинивается по сохранённому ключу. Если ключ действительно удалён из всех хранилищ и cookie — введите его вручную.

**Данные исчезли после полной очистки браузера.** Ключ нельзя восстановить. Создайте новый аккаунт.

**Вижу демо-режим.** Запущен `npm run dev` без Netlify CLI. Используйте `npx netlify dev` для серверного API.

**Звонок не соединяется.** Проверьте HTTPS, доступ к микрофону и сеть. Возможно, нужен TURN.

**Мешает «Powered by Netlify» или «Made by Netlify».** Бейдж скрывается автоматически, включая iframe Netlify с максимальным z-index. Если появится новый вариант разметки — добав селектор в `src/styles.css` и `src/main.js`. В настройках проекта Netlify также можно выключить бейдж полностью: **Project configuration → General → Powered by Netlify badge**.
